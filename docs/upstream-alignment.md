# 上游对齐与优化说明

基线提交：`b1d2dfc`。对照资料：用户提供的 `vertex-singbox-scv源码.zip`，源码根目录为 `vertex-singbox/`。压缩包未携带可核验的 Git 提交信息，本文只描述所提供快照的差异，不将其视为某个远端仓库的最新版本。

## 对比结论

当前仓库有 232 个受 Git 管理的文件；参考包有 431 个文件。大量差异来自参考包把功能移入 `internal/engine`、`internal/infra` 和 `internal/node`，不能按文件数量直接判断功能先进程度。参考包还包含实际运行配置、API 密钥文件、SQLite 数据库与 WAL；这些运行数据未引入当前仓库。

| 对比项 | 本次处理 | 原因 |
| --- | --- | --- |
| 流帧 JSON 校验 | 适配移植 | 完整但语法非法的 JSON 帧返回可重试的 502，避免静默丢帧 |
| 流完整性 | 增加真实结束信号跟踪 | 逐候选跟踪：已产出内容但没有 finishReason 就结束时返回 incomplete；不伪造 STOP，也不重放部分输出 |
| 包间空闲超时 | 适配实现 | 只计入阻塞读取上游的时间，不把下游处理慢归咎于节点 |
| 限流退避 | 移植 Retry-After 解析和透传 | 支持秒数、HTTP 日期、大小写不同的头名；上限 3600 秒，避免超大值溢出；超过 10 秒的等待交还节点冷却与接力，避免占住请求槽 |
| 日志脱敏 | 移植并扩展参考包的 redact 实现 | 覆盖 Gemini、OpenAI、Claude、代理 URL 用户信息、编码后的查询参数、转义键名及截断 JSON |
| 请求体日志 | 改为模型、请求 ID、节点等诊断元信息 | 避免调试模式或 HTTP 400 路径再次序列化整份多媒体请求，减少隐私泄漏和大对象分配 |
| 图片安全结束原因 | 补齐映射 | IMAGE_SAFETY 等图片拦截原因转换为 content_filter |
| 视频模型 | 增加明确能力守卫 | Veo 模型保留目录可见；生成请求返回不支持，避免误发 Gemini 文本端点及消耗验证码 |
| 数据库维护 | 新增管理接口及页面 | 复用现有连接池，提供空间统计、quick_check 和被动 WAL 检查点；不清空业务表 |
| TLS 依赖 | 对齐参考包版本组合 | fhttp 0.6.9、tls-client 1.16.0，以及相应传递依赖；不降级现有 SQLite、mihomo 或 Go 要求 |
| 配置后台回写 | 固定使用读取时的配置路径 | 避免异步归一化在路径切换后写入另一份配置；新增 30 轮带竞态检测的回归 |
| 请求指标 | 修正平均延迟分母 | 使用已完成请求数计算平均值，避免活跃请求越多平均延迟反而越低 |
| 构建验证 | 增加 CI 跨平台编译、版本命令 | `version` / `--version` 在规则确认及服务初始化前退出，适合构建冒烟检查 |
| OpenAI / Responses / Claude 接口 | 保留 | 参考包侧重 Gemini 原生路径，不覆盖当前四协议兼容实现 |
| sing-box 替换 mihomo | 不做架构替换 | 两者节点表示、导入、拨号及生命周期不同；直接替换会牵涉现有节点与订阅兼容，而非局部性能优化 |
| 本地 SentencePiece 分词 | 保留现有远端精确 CountTokens | 当前已有模型侧计数、缓存及并发共享；参考包的单个本地词表不能证明适配当前所有模型 |
| 强制工具 / 抗截断提示注入 | 不引入默认行为 | 会改变实际提示词、工具语义和回复格式，不应作为通用可靠性修复默认开启 |
| HTTP 正文落库、故障策略编排、远端目录抓取、新 TUI | 不整套移植 | 均涉及新的产品状态、数据库模式或上游契约；本次优先交付可独立验证的改进，保留现有配置格式及发布方式 |

## 行为与配置

新增 `stream_idle_timeout_seconds`：基础值默认 60 秒，可设为 1–1800 秒。参照上游的模型家族策略，文本首字节/包间等待为基础值的 2/1 倍，图片为 4/2 倍，TTS 为 3/2 倍；仅对 HTTP 响应体的阻塞读取计时。管理面板「设置」页支持修改并即时用于后续请求；环境变量 `VPROXY_STREAM_IDLE_TIMEOUT_SECONDS` 优先于文件配置，并在管理面板标记为托管字段。原有 `request_timeout` 继续控制单次 HTTP 请求的整体时间，未改成无限流。

缺少结束信号时，已经交付的文本继续保留，随后通过原协议的错误机制报告 incomplete。调用者不应把该响应视为成功完成。真实 STOP 后仍会继续读取尾部独立 usageMetadata 帧；不因先收到 finishReason 而丢掉用量。首轮认证的零帧 EOF、原生 Gemini 元数据回退和安全拦截保持兼容。

新增管理入口均沿用现有管理员会话、来源校验和方法限制：

| 端点 | 方法 | 用途 |
| --- | --- | --- |
| `/api/admin/db/stats` | GET | 数据库、WAL、页数和可复用空闲页空间 |
| `/api/admin/db/check` | POST | `PRAGMA quick_check(20)` |
| `/api/admin/db/checkpoint` | POST | `PRAGMA wal_checkpoint(PASSIVE)` |

维护请求受 10 秒上下文限制。PASSIVE 检查点允许读者继续工作，未能立即写回的页保留在 WAL 中；不承诺缩小 WAL 文件。完整 VACUUM、删表、清空节点等操作未添加到该页面。

基线与首轮验证使用 Go 1.26.6。漏洞扫描后，最低构建版本升至 Go 1.26.9，Docker 构建器统一到 Go 1.26.9；最终验证使用修复后的版本。修改前已在独立的基线源码快照执行全量测试并通过。新增回归覆盖四协议的缺结束帧错误、三次重试预算下不重放部分输出、尾部用量保留、畸形流帧、空闲读取中断、下游背压、Retry-After 解析和四协议透传、视频模型守卫、日志泄漏、配置迁移与环境变量，以及数据库维护的鉴权、方法限制和数据保留。
